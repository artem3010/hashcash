# 001: Server and HashCash Middleware Architecture

## Status

Accepted

## Context

В системе должен быть реализован сервер с механизмом обработки запросов через middleware на основе алгоритма Proof-of-Work (PoW). Сервер должен проверять правильность решения задачи PoW перед тем, как предоставить запрашиваемый ресурс (в данном случае "quote"). Для этой цели используется подход с хешированием (hashcash), который требует от клиента решения задачи для получения данных.

Сервер должен:
1. Принять входящие TCP-соединения.
2. Обработать запросы с использованием алгоритма PoW.
3. Если решение задачи неверное, вернуть ошибку.
4. Обработать таймауты и корректно завершить соединение.

Middleware (hashcash) должен:
1. Генерировать новый челендж для клиента.
2. Проверять корректность токенов и PoW.
3. Возвращать ошибку, если решение неверное.

## Decision

1. **Структура сервера**:
   - Сервер работает через TCP-протокол.
   - В запросе ожидаются следующие поля: метод (method), токен (token), nonce, challenge, body и ip.
   - Для обработки запроса используется middleware `HashCashMiddleware`, который проверяет решение задачи PoW.
   - Если токен или nonce неверные, сервер возвращает ошибку.
   - Налчиче токена позволяет не завязываться на одно соединение и сделать сервер stateless

2. **Обработка ошибок**:
   - Все ошибки возвращаются через сервер в виде JSON-ответа с кодом ошибки.
   - Если запрос проходит валидацию, сервер обрабатывает запрос и отправляет ответ.

3. **Middleware (HashCashMiddleware)**:
   - Генерирует челендж для клиента.
   - Проверяет правильность токенов и PoW.
   - В случае успешной проверки, передает управление следующему обработчику.
   - В случае ошибки возвращает соответствующую ошибку и не передает данные дальше.

4. **Использование таймаутов**:
   - Каждое соединение имеет дедлайн, который гарантирует завершение соединения в пределах заданного времени.

5. **Челлендж и Токены**:
   - Токен генерируется с использованием HMAC с SHA256 для предотвращения подделки.
   - Челлендж включает случайный salt, временную метку и сложность задачи.

6. **Пример обработки запроса**:
   - Клиент посылает запрос с токеном и nonce.
   - Если токен отсутствует или неверен, сервер генерирует новый челлендж.
   - Если токен корректен, сервер проверяет решение задачи PoW.
   - В случае успешной проверки сервер отправляет ответ.

# 002: Client Architecture

## Status

Accepted

## Context

Клиент должен взаимодействовать с сервером, отправляя запросы на получение данных (quote) через TCP-соединение. При этом клиент должен:
1. Проверить наличие корректного решения задачи PoW (Proof-of-Work).
2. Если токен неправильный или устарел, запросить новый челендж от сервера.
3. После получения челенджа вычислить PoW (Nonce) и вернуть запрос с решением задачи.
4. В случае возникновения ошибок (например, ошибка токена, неверное решение PoW, или ошибка сервера) клиент должен корректно обработать и вернуть ошибку.

Клиент также должен использовать таймауты, чтобы избежать зависания соединений.

## Decision

1. **Структура клиента**:
   - Клиент устанавливает соединение с сервером по TCP.
   - Для каждого запроса выполняется проверка PoW (включая токен и nonce).
   - Если токен отсутствует или некорректен, генерируется новый челендж с использованием алгоритма hashcash.
   - После вычисления решения задачи PoW отправляется запрос на сервер с токеном и nonce.
   - Ошибки от сервера обрабатываются через middleware и возвращаются клиенту.

2. **Методы клиента**:
   - **pingServer**: Проверяет подключение с сервером с помощью простого "PING"/"PONG" запроса.
   - **requestChallenge**: Запрашивает челендж от сервера (включая salt, timestamp и сложность).
   - **computePoW**: Вычисляет nonce для PoW с помощью алгоритма SHA256.
   - **GetQuote**: Основной метод, который выполняет всю логику взаимодействия с сервером (пинг, запрос челенджа, вычисление PoW и получение данных).
   - **sendFinalRequest**: Отправляет запрос с решением задачи на сервер и обрабатывает ответ.
   - **convertResponse**: Преобразует ответ от сервера в строку и обрабатывает ошибки.

3. **Обработка ошибок**:
   - Все ошибки, связанные с неправильным токеном или истечением времени, обрабатываются на уровне клиента и middleware.
   - В случае ошибки токена клиент повторно запрашивает челендж и повторяет попытку.

4. **Таймауты**:
   - Каждый запрос ограничен временем с помощью метода `SetDeadline`, чтобы избежать зависаний.

5. **Пример работы**:
   - Клиент устанавливает соединение с сервером.
   - Отправляет запрос на получение челенджа.
   - Проверяет полученный челендж и вычисляет PoW.
   - Отправляет итоговый запрос на сервер с правильным токеном и nonce.
   - Получает ответ от сервера и возвращает его в виде строки.
